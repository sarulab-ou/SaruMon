# リリース

アプリの更新元は `sarulab-ou/SaruMon` の最新の正式版 GitHub Release です。プレリリースは通常の更新対象にしません。公開リポジトリのリリースを想定しており、アプリは GitHub の認証情報を保存・要求しません。

## 配布形式

タグは `vMAJOR.MINOR.PATCH`（例: `v0.1.21`）とし、プロジェクトの `Version` と一致させます。v0.1.21 の配布ファイルは次の構成です。

| ファイル | 用途 |
| --- | --- |
| `SaruMon-0.1.21-Setup-x64.exe` | NSIS によるユーザー単位のインストーラー |
| `SaruMon-win-x64.zip` | ポータブル版・既存アプリからの更新用 |
| `SaruMon-win-x64.zip.sha256` | アプリ内更新で照合する ZIP の SHA-256 |
| `SaruMon-0.1.21-SHA256SUMS.txt` | インストーラー EXE の SHA-256 |

これらを同じ GitHub Release に配置します。ZIP 直下には自己完結型の単一ファイル `SaruMon.exe` を入れます。既存の v0.1.0 も更新用 ZIP と `.sha256` を参照するため、インストーラーを追加してもこの 2 ファイルの名前と形式は変更しません。

インストーラーの標準配置先は `%LOCALAPPDATA%\Programs\SaruMon`、設定の保存先は `%LOCALAPPDATA%\SaruMon` です。設定は更新・アンインストール時も保持します。

インストーラーの「Windows ログイン時に起動」は既定で有効です。コンポーネントの選択解除、またはサイレント実行時の `/NoStartup` で無効にできます。ZIP 版の自動起動はアプリ内で設定します。通知領域のアイコンの常時表示は Windows 側の別設定です。

ビルド成果物は Git 管理対象外です。ハッシュ照合はダウンロード破損を検出するためのもので、コード署名の代わりではありません。現在のビルド手順にコード署名処理は含まれていません。

## 公開前の確認

1. プロジェクトの `Version` を更新し、[development.md](development.md) の手順で配布物を作成します。
2. [verification.md](verification.md) の自動テスト、配布用 EXE、インストーラー、更新処理を確認し、実施結果を記録します。
3. インストーラー・EXE の版番号、ZIP の構成、全配布物のハッシュを確認します。
4. README のダウンロード案内とリリースノートを、その版で実際に配布する内容に合わせます。

自動起動を変更した版では、既定の登録、選択解除、`/NoStartup`、インストール後のアプリ内での切り替えを確認します。起動登録の確認と、通知領域のアイコンの表示位置の確認を分けて記録してください。

通信アイコンを変更した版では、左の緑の棒が上から下へ、右の赤の棒が下から上へ伸び、通信量で高さが 1 ピクセルずつ変わることを確認します。通信がない方向は空欄、未接続はオレンジの × とします。16 ピクセル表示を含め、明暗の背景で見え方を確認してください。

ユニキャスト表示の変更では、設定が既定でオフとなり再起動後も選択を保持すること、オンの間はブロードキャスト・マルチキャストだけで棒が出ないこと、ユニキャスト送受信は方向ごとに表示することを確認します。初回・切断復帰・カウンターのリセット・インタフェース変更で誤点灯しないこと、設定を切り替えても速度・合計・グラフは全体の値を保持することも確認します。1 秒のポーリングを使い、追加の ETW セッションや補助プロセス、管理者承認が発生しないことを確かめます。負荷の説明は処理構成と実測結果を分けて記録してください。

調査画面を変更した版では、選択インタフェースでの開始・停止、同じ宛先IPのTCP・UDP集約、ポートと発生元の内訳、観測の欠落表示、停止後のMarkdown・CSV保存を確認します。TCP専用表示の開始、権限確認の取り消し、終了時の補助プロセス終了も確認します。配布物へ [third-party-notices.md](third-party-notices.md) を含めます。

公開前の検証と、公開後に旧版から行うダウンロードを含む更新試験を区別してください。

## GitHub Actions

通常の push / pull request では `Build` が共通の `Package` ワークフローを呼び出します。Windows 上でテスト・配布用 EXE・ZIP を生成し、Ubuntu 24.04 上で固定版 NSIS を使ってインストーラーを作成します。

公開するコミットを確定して対応する `v*` タグを push すると、`Release` がタグとプロジェクトの版番号を検証し、同じ `Package` ワークフローで作成した成果物を GitHub Release にアップロードします。タグの push は正式版の公開操作です。ワークフローを追加しただけではリリースは公開されません。

Windows で Git / GitHub CLI を使う場合は WSL Ubuntu から実行してください。リリースワークフローの GitHub CLI は Ubuntu runner 上で実行します。
