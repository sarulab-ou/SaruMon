## 自動テスト

```powershell
$env:PYTHONUTF8 = '1'
$env:PYTHONIOENCODING = 'utf-8'
$env:CI = 'true'
dotnet run --project tests/SaruMon.Tests/SaruMon.Tests.csproj --configuration Release
```

差分計算の初回・カウンターリセット・切断と再接続・インタフェース変更、版番号とリリース情報の検証、不正 ZIP の拒否、二重起動時のプロセス間通知を確認します。

## 通信モニターの実機確認

1. 接続中のインタフェースを選び、受信・送信速度とグラフが変化することを確認します。
2. 別のインタフェースを選び、集計と表示が対象に切り替わることを確認します。
3. 対象を切断・再接続し、未接続表示と計測の復帰を確認します。検証で業務用の接続を切らないよう、検証用アダプターを使います。
4. × と最小化の両方で監視が継続し、通知領域のアイコンからウィンドウを開けることを確認します。
5. EXE をもう一度起動し、既存ウィンドウが表示されて、常駐プロセスが重複しないことを確認します。
6. 再起動後のインタフェース選択、ログイン時の自動起動の有効・無効、メニューからの終了を確認します。

## ローカル更新処理

配布用 EXE をビルドしてから実行します。

```powershell
./scripts/test-updater.ps1
```

`artifacts/updater-smoke/` の検証用コピーで、終了待ち、EXE の置き換え、再起動、二重起動、更新対象のハッシュが変わった場合の拒否を確認します。入力となる配布用 EXE は変更しません。エラーケースでは検証用スクリプトのエラーダイアログだけをファイル出力へ置き換えます。

これは GitHub API の確認や公開ファイルのダウンロードを含む試験ではありません。新しい正式版の公開後、旧版の **ヘルプ → 更新を確認** から、ダウンロード、ハッシュ照合、版番号、再起動、設定の保持を確認します。

## インストーラー

インストーラーを作成した後、分離した検証用プロファイルを使うスモークテストを実行します。

```powershell
./scripts/test-installer.ps1
```

2026-11-26 に、次の 9 グループが成功しました。検証用の登録名・設定保存先・ショートカット名を使用し、通常の SaruMon の登録と分離しています。

| グループ | 確認した内容 |
| --- | --- |
| 初回インストール | ファイル配置、アプリ登録、スタートメニューと任意のデスクトップショートカット |
| 再インストール | インストール先に利用者が追加したファイルを保持 |
| EXE の書き込みロック | EXE をロックした状態でインストールとアンインストールを拒否 |
| 所有情報の不整合 | インストール先の識別情報が不正な場合、インストールとアンインストールを拒否 |
| アンインストール | 既知の配布ファイルとそのコピーの自動起動登録だけを削除し、利用者のファイルと設定を保持 |
| 任意設定・別コピー | デスクトップショートカットの初期値が無効で、別コピーを指す自動起動登録を保持 |
| 不完全なインストール | EXE などが欠けた状態でも残りの配布ファイルと登録を削除 |
| 無関係なフォルダー | 既存ファイルがある、SaruMon の管理対象ではないフォルダーへのインストールを拒否 |
| 実環境との分離 | 通常の SaruMon のレジストリ登録が試験前後で変わらない |

ドライブ直下（例: `C:\`）へのインストールを拒否する処理はソースで確認しました。拒否処理に不具合があった場合に検証範囲外へ書き込むことになるため、実際のドライブ直下を対象とする試験は実行していません。

インストール後のアプリ内更新全体と、通常のアプリ登録名を使った実環境での導入・削除は、この分離試験の結果には含めません。
